## 2. Detailed File Structures & Responsibilities

### 1. `BaselinePanel.tsx`
- **Purpose:** Demonstrates how standard/naive competitor LLM architectures (the 95% baseline) fail under real-world street market conditions.
- **Props:**
  - `baseline?: BaselineResult` (`latencyMs`, `rawLLMOutput`, `crashedOrHallucinated`, `failureReason`).
- **Internal Logic & Render:**
  - If `crashedOrHallucinated` is `true`, switches container styling to error red (`cardError`).
  - Displays latency tag and raw LLM stream text.
  - Displays an alert banner highlighting specific failure modes (e.g., NaN float underflows, clock drift hallucination, 85dB noise corruption).

### 2. `EnginePanel.tsx`
- **Purpose:** Displays the 0.5% Cascade Core Engine's resilient epistemic state, interval bounds, and invariant protection.
- **Props:**
  - `engine?: EngineResult` (`epistemicState`, `primaryDecision`, `bounds`, `invariantViolationsDetected`, `abstained`, `latencyMs`).
- **Internal Logic & Render:**
  - Dynamically changes border & background based on epistemic state (`cardSuccess` for verified decisions vs. `cardAbstained` in amber when uncertain).
  - Displays mathematical interval bounds `[minEstimate, maxEstimate]` with `±uncertaintyInterval`.
  - Shows caught invariant violations tag (`🛡️ Invariant Caught`).
  - Shows sub-millisecond to low-millisecond offline engine latency.

### 3. `SabotageControls.tsx`
- **Purpose:** Live interactive toolbar for hackathon judges to inject hostile edge conditions during live demonstrations.
- **Props:**
  - `currentScenario: SabotageType`
  - `onSelectScenario: (scenario: SabotageType, intensity: number) => void`
- **Scenarios Offered:**
  1. `NONE_CLEAN` (Clean normal path, intensity 0)
  2. `NOISE_85DB` (85dB ambient market noise & soundbox chatter, intensity 85)
  3. `CLOCK_DRIFT_1970` (Simulated dead-battery clock reset to 1970, intensity 100)
- **Behavior:** Triggers comparative re-rendering across `BaselinePanel` (showing crash/hallucination) vs `EnginePanel` (showing monotonic HLC protection and interval abstention).

### 4. `LossModal.tsx`
- **Purpose:** Bayesian stock loss / spoilage attribution bottom sheet for perishable commodities.
- **Props:**
  - `visible: boolean`, `onClose: () => void`, `onCalculate?: (spoilage: number, eating: number, theft: number) => void`
- **User Inputs:**
  - Commodity chip selector (`Tomatoes`, `Onions`, `Potatoes`).
  - `missingKg` (numeric input, e.g. 4.0 kg).
  - `temp` (ambient temperature in °C, e.g. 39°C).
  - `hoursExposed` (exposure duration in heat, e.g. 7 hours).
- **Core Formula:**
  - Bayesian temperature-accelerated exponential rot factor:
    $$\text{rotBase} = \operatorname{clamp}_{15}^{75}((T - 25) \times 3.2 + (H \times 1.8))$$
    $$\text{eatingBase} = \max(10, 85 - \text{rotBase})$$
    $$\text{theftBase} = \max(5, 100 - (\text{rotBase} + \text{eatingBase}))$$
- **Render Output:**
  - Visual breakdown bars: Heat Spoilage %, Family Use %, Other Loss / Theft %.
  - "Save changes" updates state in `App.tsx`.

### 5. `EODReconciliationModal.tsx`
- **Purpose:** End-of-Day (EOD) physical cash drawer settlement and automated discrepancy attribution.
- **Props:**
  - `visible: boolean`, `onClose: () => void`, `uncommittedHypotheses?: AudioHypothesisBundle[]`, `confirmedUpiTotal?: number`, `onReconciliationComplete?: (result: EODReconciliationResult) => void`
- **Inputs:**
  - `openingFloat`: Opening cash float (₹).
  - `closingPhysicalCash`: Counted physical cash at closing (₹).
  - `knownCashExpenses`: Day's cash expenses/fuel (₹).
- **Calculations:**
  - $\text{targetCashDelta} = \text{closingCash} - \text{openingFloat} + \text{knownExpenses}$
  - Reconciles against speech-discovered cash transactions.
  - Computes $\text{drawerDiscrepancy} = \text{targetCashDelta} - \text{totalResolvedCash}$.
  - Attributes slack tag: `BALANCED`, `SMALL_DIFFERENCE` ($\le ₹20$), `CASH_TO_CHECK` (shortfall), `SALES_TO_CHECK` (unaccounted surplus).
- **Render:**
  - Expected cash vs. sales counted vs. discrepancy.
  - Color-coded discrepancy badge.
  - Confirmed sales itemized list.

### 6. `CustomNoticeModal.tsx`
- **Purpose:** Reusable, high-polish alert/confirmation dialog adhering to the product design system.

## 3. UI Design Tokens & Styling Guide

- **Primary Brand Color:** Deep Forest Green (`#073B3A`)
- **Accent High-Energy Color:** Electric Lime (`#E2FD52`)
- **Light Tint Backgrounds:** Soft Lime Tint (`#F1FFE5`), Soft Mint (`#F8FBFA`)
- **Border / Divider:** Soft Sage Border (`#DDECE7`), Neutral Gray (`#E5E7EB`)
- **Typography:**
  - Headings: Heavy 800/900 weight, -0.3 tracking.
  - Body: 500/600 weight, 18–20 line height.
- **Elevation / Radius:**
  - Modals: 24–28px rounded corners, bottom sheet slide or fade.
  - Buttons: 18–20px rounded pill buttons with slight glow shadows.
